## 二、设计前的“自问自答”（每个问题选一个最优答案）

**Q1：设置界面按下 PA5 后，倒计时应该进入哪一步？**
A：**直接进入编辑界面（时分秒 = 00:00:00，默认选中“秒”字段）**。理由：与旧版“PA5 → 倒计时编辑界面”
的肌肉记忆一致，不新增任何中间页；运行中的倒计时再次进入时切到进度界面而不是清零。

**Q2：“被选中的图案的正方形边框要闪烁”——闪烁频率与占空比怎么定？**
A：**400 ms 亮 / 400 ms 灭（周期 0.8 s）**。理由：人眼最容易识别、不刺眼，也便于与倒计时 1 s 过渡
动画区分；图案本身始终不闪（符合要求“里面的图案不用闪烁”）。

**Q3：长按 2 秒这一动作会不会在松手时误触发短按功能？**
A：**必须不会**。因此按键驱动把“短按”定义为 `Key_Release()`（抬起且按住时间 < 2 s 才产生），
凡是“短按=切字段/换选择”的地方都用它，长按只走 `Key_Long()`。这样实物上就不会出现
“长按返回时间界面时，顺手把选中项改了”的问题。

**Q4：“回到时间界面后 1 秒内不能通过 PA4 切换节目”——锁在哪些场景生效？**
A：**从设置界面、倒计时界面（含进度界面）、秒表界面返回时间界面后都生效**；且只锁 PA4 的节目切换，
不锁 PA5、不锁下一次进入子界面。锁的起点是“返回那一刻”，1 秒后自动失效，无需额外操作。

**Q5：秒表界面「黑屏」如何实现才最稳？**
A：进入时清空显存并刷新一次，之后**停止刷新**（`s_stopFresh`），屏幕保持全黑且不占 I2C 带宽；
长按 PA4 返回后照常恢复刷新。后续开发秒表只需把清屏换成绘制即可。

**Q6：PNG 里的“钝角正方形”是圆角还是切角？**
A：**圆角（R=10）**。“钝角”在几何上指大于 90° 的角，圆角过渡天然满足；且用“四直边 + 四段
四分之一圆弧、端点重合”的构造保证像素级**连续、不断开、不重复**。

**Q7：两个图标怎么画才像上传的两张照片？**
A：按照片的“大色块剪影”特征：铃铛 = 圆顶钟体 + 外扩下沿 + 独立钟舌 + 左右各两道声波弧；
秒表 = 实心圆环（2 px 外圈）+ 12 点刻度 + 指向 10 点的指针 + 中心轴。1 bit OLED 上做黑白反相
（照片里橙色实心 → 屏上白色实心；照片里白色线条 → 屏上黑色线条）。

**Q8：浏览器模拟器怎么做到“和实物一模一样”？**
A：**不重写动画，直接编译同一份 C 代码**。用 zig/clang 把 10 个 `.c` 编成 `wasm32`，
用一份寄存器内存映射桩（`simulator/hal/stm32f10x.h`）替代标准外设库，页面负责：
写 `TIM2->CNT`（10 tick/ms，与 PSC=7199 完全一致）、写 `GPIOA->IDR`（PA4..PA7）、
读回 LED/蜂鸣器引脚与 `OLED_GRAM`。因此开机动画、1 秒过渡、闪烁相位、长按判定全部一致。

**Q9：如何在不影响 Keil 的前提下做这些模拟器改动？**
A：所有模拟器代码都在 `#if defined(FW_SIMULATOR)` 内，Keil 编译时完全不存在；
`DS18B20.c` 的 DWT 重定向、`OLED.c` 的延时省略、`LED.c` 的引脚状态镜像也是如此。
模拟器专用的 `main()` 改名（`-Dmain=Fw_Main`）只发生在 wasm 构建脚本里。

**Q10：如何证明“旧功能没被破坏”？**
A：把 8 项旧功能写成 73 条可执行断言（表盘/黑洞切换、倒计时全流程、取消、LED、蜂鸣器节奏、
烟花+猫、温度、性能），在真实固件镜像上跑，全部通过；并且测试通过 HTTP 加载 wasm,
与浏览器走同一条代码路径。
